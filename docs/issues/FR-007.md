# [FR-007] Project State Persistence & Local SQLite Cache

## Labels
`MUS`, `enhancement`, `database`, `sqlite`, `persistence`

## User Story
As a user, I want my projects, parsed chapters, audio caches, and editing history to be auto-saved locally so that I can close the app and resume producing my audiobook anytime without losing progress.

## Proposed Solution

### Overview
Integrate embedded SQLite (`rusqlite`) in Tauri. Each imported book becomes a Project. Chapters, sentences, audio file links, and custom voice parameters are stored in SQLite in `%APPDATA%/book-studio/data.db`.

### Implementation Flow
1. App startup checks and runs SQLite migrations:
   - `projects` table (id, title, author, file_path, cover_path, created_at, updated_at).
   - `chapters` table (id, project_id, index, title, text_raw).
   - `sentences` table (id, chapter_id, index, raw_text, clean_text, audio_path, duration, status, voice, temperature).
2. Auto-save state after every text edit or audio synthesis.
3. "Recent Projects" screen allows opening previous books instantly without re-parsing.

### Technical Approach

```sql
CREATE TABLE IF NOT EXISTS projects (
    id TEXT PRIMARY KEY,
    title TEXT NOT NULL,
    author TEXT,
    cover_path TEXT,
    created_at DATETIME DEFAULT CURRENT_TIMESTAMP
);

CREATE TABLE IF NOT EXISTS sentences (
    id TEXT PRIMARY KEY,
    chapter_id TEXT NOT NULL,
    sentence_idx INTEGER NOT NULL,
    text TEXT NOT NULL,
    audio_path TEXT,
    duration REAL,
    status TEXT DEFAULT 'pending',
    FOREIGN KEY(chapter_id) REFERENCES chapters(id)
);
```
